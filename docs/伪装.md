# 客户机伪装

默认配置下客户机到处写着「我是虚拟机」。玩家在游戏里"入侵"的每一台机器
都长成同一副 QEMU 的样子，沉浸感直接没了。

这一层把那些痕迹抹掉，并且给每台机器一个可辨认的身份。

## 默认都漏了什么（实测）

M0 的探针 `m0/probe/` 在打补丁前的抓取结果：

| 探测方式 | 默认输出 |
| --- | --- |
| `uname -a` | `Linux main 6.18.52-0-virt #1-Alpine SMP …` |
| `cat /proc/version` | `… (buildozer@build-3-23-x86_64) (cc (Alpine 15.2.0) …)` |
| `cat /proc/cmdline` | `console=ttyS0 quiet loglevel=3 m0.host=main m0.ip=… m0.root=/dev/vda` |
| `/proc/cpuinfo` | `AuthenticAMD` / `QEMU Virtual CPU version 2.5+` |
| `/sys/class/dmi/id/*` | `QEMU` / `Standard PC (Q35 + ICH9, 2009)` / `SeaBIOS` |
| `/sys/class/net/eth0/device/vendor` | `0x1af4`（Red Hat virtio） |
| `ls /sys/block` | `vda` |
| `dmesg` | 337 行，含 DMI、SeaBIOS、`QEMU DVD-ROM`、`virtio_blk` |
| `ls /etc` | `m0-common.sh`（我们自己的启动脚本） |

其中 `/proc/cmdline` 最要命：它把游戏的内部协议（`m0.*`）整排摊给玩家看。

## 分两层做掉

**宿主侧**（`GameHacker.Core.Qemu.HardwarePersona`）——全是 QEMU 原生参数，
不需要魔改：

* `-smbios type=0/1/2/3` 改 BIOS、整机、主板、机箱的厂商与型号
* `-cpu <具名型号>,model-id=<字符串>` 改 `/proc/cpuinfo` 的 `vendor_id` 和 `model name`
* `-device e1000e`（Intel 82574L，`0x8086:0x10d3`）替掉 `virtio-net-pci`
* `-device ide-hd,bus=ide.0,model=…,serial=…` 走 q35 内建的 ICH9 AHCI，
  根设备从 `/dev/vda` 变成 `/dev/sda`

换网卡和磁盘之后客户机的 PCI 拓扑里一个 virtio 设备都不剩，
只有 Q35 host bridge + 82574L + ICH9 AHCI + ICH9 SMBus，和真机一模一样。

**客户机侧**（`m0/guest/common.sh` 的 `m0_disguise`）：

* `mount --bind` 覆盖 `/proc/version` 和 `/proc/cmdline`
  （procfs 支持对单个文件做 bind mount，实测可行且 `umount` 后原样恢复）
* 把 `/bin/uname` 从 busybox 的软链换成一个自己的壳子
* `dmesg -c > /dev/null` 清掉内核环形缓冲区
* 把启动脚本从 `/etc/m0-common.sh` 挪到 `/lib/m0/common.sh`，
  stage2 装成 `/sbin/init`（真机上本来就该有这个文件），
  启动末尾再往 `/lib/m0` 上盖一层空 tmpfs

### 两个必须小心的顺序问题

1. `m0_disguise` 一定要在**所有** `m0_cmdline_get` 调用之后跑 ——
   盖掉 `/proc/cmdline` 之后就再也读不到真实参数了。
2. 内核 cmdline 按空格分词，值里不能带空格。宿主侧把空格换成 `~`，
   客户机侧 `m0_unesc` 还原。`HardwarePersonaTests` 盯着这条。

### 版本号不写死

`uname -r` 不是填一个固定字符串，而是把真实版本的 `-virt` 后缀换成 `-lts`
（`HardwarePersona.KernelFlavor`）。写死的话每次升级客户机内核都要跟着改，
迟早和 `/proc/version`、`/lib/modules/` 对不上 ——
那种"版本号自己打架"的破绽比 `-virt` 本身还刺眼。

### 发行版默认不改

`OsPrettyName` 默认留空，也就是不动 `/etc/os-release`。
客户机是货真价实的 Alpine + busybox，硬说自己是 Ubuntu 的话
`/etc/apk` 还在、`dpkg` 又没有，处处对不上，比不伪装还假。
要做架空发行版时再填这几个字段。

## 挡不住什么

| 探测方式 | 结果 | 为什么 |
| --- | --- | --- |
| `busybox uname -r` | 仍是 `…-virt` | 直呼 applet，绕开了 `/bin/uname` |
| CPUID 的 hypervisor 位 | 仍是 1 | 要改得动 TCG |
| 时间侧信道（RDTSC 抖动） | 测得出来 | 同上 |

前两条只有换成**自建内核**才能根治：自己 `make` 的话
`CONFIG_LOCALVERSION` 直接决定 `uname -r`，`KBUILD_BUILD_USER/HOST`
决定 `/proc/version`，从源头上就没有 `-virt` 这个字样，
也不需要 `/bin/uname` 壳子。顺带还能把 e1000e、AHCI、ext4 编进内核，
initramfs 里少三个模块、启动更快。

代价是多一条构建链（内核源码 + 配置 + 十几分钟编译）。
当前这层已经挡住了玩家在游戏里会做的所有常规侦察，
自建内核留给真正需要"反检测"成为玩法的时候再做。

## 回归防护

`SelfTest`（`GAMEHACKER_SELFTEST=<报告路径>`）里有 7 条伪装断言，
读的是 libtsm 渲染后的屏幕文本，走完整的键盘 -> 客户机 -> 渲染链路。
三端验证脚本会跑它，因为 `-smbios` / `-cpu` 是 QEMU 的能力，
不同平台的构建未必一致。

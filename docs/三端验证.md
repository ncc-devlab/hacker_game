# 三端验证（Windows 先行）

## 为什么需要单独验证

M0/M1 的测试都在 Linux 上跑，而且走的是裸串口 —— 绕开了 Godot 的输入链
和 godot-xterm 的 GDExtension，而这两样恰恰是换平台最容易坏的地方。
另外 Windows 上用的 QEMU 不是我们自己裁剪的那份，伪装依赖的
`-cpu IvyBridge`、`e1000e`、`ich9-ahci` 不能假定都在。

## 步骤

**在 Linux 上**（镜像只能在这里构建）：

```sh
scripts/pack-for-windows.sh          # -> m0/run/windows-bundle.zip（约 53MB）
```

包里是三个客户机镜像，外加 godot-xterm 插件（有了它 Windows 端可以不联网）。

**在 Windows 上**，需要：

* **.NET SDK** 8 或更新版本（推荐 10）。注意是 **SDK**，不是 Runtime / Desktop Runtime ——
  只装运行时的话 C# 编译不出来，Godot 会报 `Cannot instantiate C# script ... Main.cs`
  然后空转到超时（第一轮 Windows 验证就是这样）。.NET Framework 4.8.x 是另一套东西，和这里无关。
  开发机只有 .NET 10 SDK、没有 8 运行时，全部测试照样通过，所以 10 SDK 足够。
* Godot 4.7 **.NET 版**（用 `*_console.exe`，非 console 版不往 stdout 写日志）
* QEMU：<https://qemu.weilnetz.de/w64/> 的官方构建装到默认位置即可，
  或者放到 `runtime\windows-x86_64\bin\`

把 zip 解到仓库根，然后：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-windows.ps1
# Godot 不在常见位置时：
powershell -ExecutionPolicy Bypass -File scripts\verify-windows.ps1 -Godot D:\path\Godot_v4.7.2-stable_mono_win64_console.exe
# 加一轮带窗口的截图：
...\verify-windows.ps1 -Windowed
```

跑完会生成 `m0\run\verify-<时间戳>.zip`，**把它发回来**就行。

## 脚本检查什么

| 步骤 | 内容 |
| --- | --- |
| 环境 | 系统版本、CPU、内存（非 x86_64 主机会警告：只能纯 TCG） |
| .NET | SDK 版本 |
| QEMU | 能否启动；是否有 IvyBridge/Westmere、e1000e、ich9-ahci/ide-hd |
| 镜像 | 三个文件是否就位 |
| Core 测试 | `dotnet test`，含真实起 QEMU、过交换机、ping 通的集成测试 |
| Godot | 是否 mono 版、GDExtension 的 Windows dll 是否在、C# 编译、资源导入 |
| 自检 | `SelfTest` 全部断言：焦点、键盘经 Godot 输入链到客户机、Tab 补全、ANSI 渲染、7 条伪装 |
| 残留 | 退出后有没有孤儿 `qemu-system*`（TCG 每台吃满一核） |

zip 里有：`report.txt`（逐项 PASS/FAIL）、`transcript.txt`（完整控制台）、
每一步的 stdout/stderr、`selftest.txt`、`capture.pcap`（能直接用 Wireshark 打开）、
`qemu-capabilities.txt`，以及 Godot 自己的 `user://logs`。

⚠ 缺镜像时 Core 的集成测试会**跳过**而不是失败，`dotnet test` 那一行
会显示通过 —— 看 `已跳过` 的数字，或者看第 4 步镜像检查。

## 这个脚本自己的验证程度

在 Linux 上用 PowerShell 7 做过语法解析（0 错误），并扫过一遍
5.1 不支持的记号（`&&` `||` `??` 三元，0 处）。文件存的是带 BOM 的 UTF-8 ——
5.1 读无 BOM 的文件会按本地代码页解码，中文全乱。
**但没有在真实 Windows 上执行过**，第一次跑出问题请连 zip 一起发回来。

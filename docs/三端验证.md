# 三端验证（Windows 先行）

## 为什么需要单独验证

M0/M1 的测试都在 Linux 上跑，而且走的是裸串口 —— 绕开了 Godot 的输入链
和 godot-xterm 的 GDExtension，而这两样恰恰是换平台最容易坏的地方。
另外 Windows 上用的 QEMU 不是我们自己裁剪的那份，伪装依赖的
`-cpu IvyBridge`、`e1000e`、`ich9-ahci` 不能假定都在。

## 步骤

**在 Linux 上**（镜像只能在这里构建）：

```sh
scripts/pack-for-windows.sh          # -> m0/run/windows-bundle.zip（约 53MB）
```

包里是三个客户机镜像，外加 godot-xterm 插件（有了它 Windows 端可以不联网）。

**在 Windows 上**，需要：

* **.NET SDK** 8 或更新版本（推荐 10）。注意是 **SDK**，不是 Runtime / Desktop Runtime ——
  只装运行时的话 C# 编译不出来，Godot 会报 `Cannot instantiate C# script ... Main.cs`
  然后空转到超时（第一轮 Windows 验证就是这样）。.NET Framework 4.8.x 是另一套东西，和这里无关。
  开发机只有 .NET 10 SDK、没有 8 运行时，全部测试照样通过，所以 10 SDK 足够。
* SDK 必须是 **x64** 版。32 位和 64 位 dotnet 是两套独立安装
  （`C:\Program Files\dotnet` 与 `C:\Program Files (x86)\dotnet`）。只装了 x86 SDK 时，
  命令行编译、测试、自检**全都能过**，但双击用 Godot 编辑器打开工程会报
  `Could not load file or assembly 'Microsoft.Build(.Framework), Version=15.1.0.0'`
  （日志里是 `BadImageFormatException`）：64 位编辑器要加载 SDK 里的 `Microsoft.Build.dll`，
  而 SDK 里的程序集是按位数预编译的。第二轮 Windows 验证 14/14 通过，手动打开编辑器才撞上。
  脚本现在单列"SDK 是 64 位"和"编辑器能加载 MSBuild"两项。
* Godot 4.7 **.NET 版**（用 `*_console.exe`，非 console 版不往 stdout 写日志）
* QEMU：<https://qemu.weilnetz.de/w64/> 的官方构建装到默认位置即可（游戏会自己去
  `C:\Program Files\qemu` 找，不需要改 PATH、不需要 `GAMEHACKER_QEMU`），
  或者放到 `runtime\windows-x86_64\bin\`

把 zip 解到仓库根，然后：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-windows.ps1
# Godot 不在常见位置时：
powershell -ExecutionPolicy Bypass -File scripts\verify-windows.ps1 -Godot D:\path\Godot_v4.7.2-stable_mono_win64_console.exe
# 加一轮带窗口的截图：
...\verify-windows.ps1 -Windowed
```

跑完会生成 `m0\run\verify-<时间戳>.zip`，**把它发回来**就行。

## 脚本检查什么

| 步骤 | 内容 |
| --- | --- |
| 环境 | 系统版本、CPU、内存（非 x86_64 主机会警告：只能纯 TCG） |
| .NET | SDK 版本 |
| QEMU | 能否启动；是否有 IvyBridge/Westmere、e1000e、ich9-ahci/ide-hd |
| 镜像 | 三个文件是否就位 |
| Core 测试 | `dotnet test`，含真实起 QEMU、过交换机、ping 通的集成测试 |
| Godot | 是否 mono 版、GDExtension 的 Windows dll 是否在、C# 编译、资源导入 |
| 自检 | `SelfTest` 全部断言：焦点、键盘经 Godot 输入链到客户机、Tab 补全、ANSI 渲染、7 条伪装 |
| 残留 | 退出后有没有孤儿 `qemu-system*`（TCG 每台吃满一核） |

zip 里有：`report.txt`（逐项 PASS/FAIL）、`transcript.txt`（完整控制台）、
每一步的 stdout/stderr、`selftest.txt`、`capture.pcap`（能直接用 Wireshark 打开）、
`qemu-capabilities.txt`，以及 Godot 自己的 `user://logs`。

⚠ 缺镜像时 Core 的集成测试会**跳过**而不是失败，`dotnet test` 那一行
会显示通过 —— 看 `已跳过` 的数字，或者看第 4 步镜像检查。

## 这个脚本自己的验证程度

在 Linux 上用 PowerShell 7 做过语法解析（0 错误），并扫过一遍
5.1 不支持的记号（`&&` `||` `??` 三元，0 处）。文件存的是带 BOM 的 UTF-8 ——
5.1 读无 BOM 的文件会按本地代码页解码，中文全乱。
**但没有在真实 Windows 上执行过**，第一次跑出问题请连 zip 一起发回来。

# macOS 与 Linux

两端共用 `scripts/verify.sh`（`scripts/verify-macos.sh` 是它的别名）：

```sh
scripts/verify.sh              # 只检查，不装东西
scripts/verify.sh --install    # 缺什么装什么，不需要 sudo（Linux 上 QEMU 请用包管理器装）
```

`--install` 会装：.NET 10 SDK（`dotnet-install.sh`，装到 `~/.dotnet`）、
QEMU（`brew install qemu`，约 700MB）、Godot 4.7.2 .NET（`~/Applications/Godot_mono.app`）、
godot-xterm 插件。客户机镜像同样要从 Linux 拷过来（`scripts/pack-for-windows.sh` 的包与平台无关）。

产出在 `m0/run/verify-<macos|linux>-<时间戳>.zip`，检查项和 Windows 版一一对应。

## 脚本里处理掉的 macOS 特有问题

* **系统自带 bash 是 3.2**：不用关联数组、`mapfile`、`${x,,}`
* **没有 `timeout` 命令**：超时和"日志里出现致命错误就提前结束"都在轮询循环里自己做
* **dotnet 不在 PATH 上**：`dotnet-install.sh` 装到 `~/.dotnet`，ssh 进来的非登录 shell
  也拿不到 `/opt/homebrew/bin`。脚本按固定位置去找，并设好 `DOTNET_ROOT`
  （Godot 靠它找到 .NET 运行时）
* **从 Finder 启动的程序同样拿不到 `/opt/homebrew/bin`**：游戏自己会去 Homebrew / MacPorts
  的默认位置找（`QemuLocator`）。脚本**不再**替游戏设 `GAMEHACKER_QEMU`（除非给了 `--qemu`），
  这样自检通过就说明"双击就能跑"
* **quarantine 属性**：浏览器下载的 Godot.app 会被 Gatekeeper 拦；插件的 `.framework`
  带着它会静悄悄加载失败。脚本检查并提示（`--install` 时直接解除插件的）

## 没有 .NET 时 Godot 会卡死

Godot mono 找不到 .NET 运行时时，报一行
`.NET: One of the dependent libraries is missing ... hostfxr` 然后**不退出**——
连 `--import` 都这样。两个脚本都在没有 SDK 时跳过这几步，并把 `hostfxr` 挂成失败模式兜底。
修之前在 Mac 上白等 304 秒，修之后 3 秒出结论。

## 实测结果（Apple M4，macOS 26.4.1，16GB）

2026-09-22，在远程 Mac 上用最小 PATH（`env -i PATH=/usr/bin:/bin:...`）跑：**14/14 通过**。

| 项目 | 结果 |
| --- | --- |
| Core 测试（含真实起 x86_64 客户机的集成测试） | 33/33，8 秒 |
| Godot 自检 | 12/12，49 秒 |
| 两台虚拟机就绪 | 3.1 秒（含 Godot 自身启动） |
| 残留 qemu | 0 |

**Apple Silicon 上的启动耗时不是问题。** QEMU 在这台机器上只有 `tcg` 一种加速器
（HVF 只加速 arm64 客户机），但启动耗时和 Linux x86_64 上几乎一样——
对我们这种体量的客户机，TCG 完全够用。

没测到的：`--install` 路径（机器上已经装好了；这几步就是首次手工搭环境时执行的命令），
带窗口运行（ssh 会话拿不到图形界面），以及正式发行要面对的公证与 JIT entitlement
（brew 的 QEMU 没有签名，不涉及）。

# QEMU 查找顺序（游戏与测试共用 `QemuLocator`）

1. 环境变量 `GAMEHACKER_QEMU`（给了就用，哪怕文件不存在——让报错说清楚是哪个路径）
2. 随游戏发布的 `runtime/<平台>/bin/`
3. 平台默认安装位置：Windows `C:\Program Files\qemu`；macOS `/opt/homebrew/bin`、`/usr/local/bin`、`/opt/local/bin`
4. PATH

第二轮 Windows 验证里，编辑器直接运行时必须手动设 `GAMEHACKER_QEMU`：官方安装包不改 PATH，
而游戏原先只看环境变量、`runtime/` 和 PATH。都找不到时状态栏会按平台说明怎么装。

两个验证脚本的"残留 qemu"检查只算命令行里带 `m0-guest.cpio.gz` 的进程，
开发机上别的虚拟机既不计数也不会被杀。

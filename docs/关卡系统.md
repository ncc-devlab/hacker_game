# 关卡系统

MVP2 的第一块：选关界面和关卡格式。跳板扫描的内容还没做，这里先把「选一关 → 进去 → 按步骤推进 → 通关存档 → 解锁下一关」的管线跑通。

## 流程

```
LevelSelect.tscn（主场景）──选关──▶ Level.tscn ──返回 / 通关──▶ LevelSelect.tscn
        ▲                                  │
        └──── GameState（autoload）────────┘
              关卡目录 · 通关进度 · 当前关卡
```

- 场景切换用 `ChangeSceneToFile`。旧场景整个释放，所以当前关卡放在常驻的 `GameState` 上传递。
- 离开关卡时由 `Level._ExitTree` 同步关掉虚拟机，和以前退出游戏走同一条路。
- 进度存在 `user://progress.json`，只记「完成了哪些关」。解锁状态按 `requires` 现算，所以改了关卡依赖，老存档也自动对得上。
- 存档损坏时不会让游戏打不开：进度按空处理，选关界面底部会提示。

## 关卡文件

放在 `src/GameHacker.Godot/levels/<id>.json`，文件名要和 id 一致。可以写 `//` 注释。

```jsonc
{
  "id": "lab-ping",              // 存档里记的就是它；只用小写字母、数字、连字符
  "title": "联网实验场",
  "track": "tutorial",           // tutorial 教学 | mission 实战
  "order": 0,                    // 同一条线里的排序
  "status": "playable",          // playable | draft（草稿关只有编辑器里能进，步骤可以没有判定）
  "requires": [],                // 先完成哪些关
  "summary": "一句话",
  "briefing": "任务简报",
  "networks": [                  // 每个网段是交换机上的一个 VLAN
    { "name": "lan", "vlan": 1, "subnet": "10.0.0.0/24" }
  ],
  "machines": [                  // 第一台是玩家的机器
    { "name": "web01", "nics": [ { "network": "lan", "ip": "10.0.0.1" } ],
      "persona": "workstation", "disk": "alpine-main", "memory": 512 },
    { "name": "backup", "nics": [ { "network": "lan", "ip": "10.0.0.2" } ], "persona": "legacy-server" }
  ],
  "steps": [
    { "id": "link", "title": "两台机器互通", "hint": "…",
      "check": { "type": "ping", "from": "backup", "to": "web01" } }
  ]
}
```

加载时（`LevelCatalog.Parse`）会一次性校验下面这些，发现的错误攒齐了一起报：

- 字段名拼错
- 网段：VLAN 号超出 1..4094 或重复、subnet 写错或主机位不为零
- 网卡：接了不存在的网段、IP 不在所接网段里、占用网络地址或广播地址、一台机器两块网卡接同一个网段、网卡数不在 1..4
- 检测类型不存在
- 检测条件引用了不存在的机器
- id 或机器名重复
- IP 不合法
- 人设不存在
- `requires` 指向不存在的关，或者解锁条件成环
- 可玩关的某一步没有判定

单元测试 `仓库里的关卡文件都能通过校验` 会把仓库里的关卡文件全部过一遍。

## 网段与 VLAN

交换机上每个 VLAN 开一个监听口，全部是 access 口。虚拟机的网卡连到哪个口，就属于哪个 VLAN。

- **身份由连接决定。** 客户机看到的是普通网卡，不知道也改不了自己在哪个 VLAN。
- **帧只在同一 VLAN 内转发。** MAC 表按 (VLAN, MAC) 分开学，广播也只在本 VLAN 内泛洪。
- **客户机自己打了 802.1Q / QinQ 标签的帧一律丢弃。** 否则玩家手工造一个带标签的帧，就能跳进别的 VLAN。
- **多网卡。** 网卡按顺序成为客户机里的 eth0、eth1……，eth0 的地址经内核参数 `m0.ip` 传进去，eth1 起是 `m0.ip1`、`m0.ip2`。跳板机就是一块网卡在外网、一块在内网。
- **抓包。** 面板多了 VLAN 列，过滤框输入 `vlan20` 就只看这个网段。导出的 pcap 会给每帧补上 802.1Q 标签，Wireshark 里可以按 `vlan.id` 过滤。

**多层内网怎么叠。** 一层一个 VLAN，层与层之间放一台双网卡的机器（跳板机就是这个形状）：外网 → 办公网 → 核心网，就是 3 个 VLAN 加两台跳板机。层数不受限，一台机器最多 4 块网卡。测试 `多层内网_每层只和自己这层通` 覆盖了三层的情况。

现在**还没有**、等关卡真要用再加的东西：

| 缺的能力 | 什么时候需要 | 备注 |
| --- | --- | --- |
| trunk 口（一块网卡带多个 VLAN 的标签） | 想让玩家玩 VLAN 跳跃，或者一台机器要看多个网段又不想插那么多网卡 | 现在 access 口一律丢弃带标签的帧，加 trunk 时要把「哪些口允许带标签」做成配置 |
| 三层转发与访问控制（路由器 / 防火墙） | 层与层之间要能按端口放行，而不是全通或全不通 | 现在跨层只能靠双网卡的机器自己转发 |
| 关卡格式里的网关与路由 | 玩家机需要一条指向内网的路由 | 跳板扫描是走隧道过去的，暂时用不上 |

集成测试 `跳板拓扑_两块网卡各进一个_VLAN_外网够不着内网` 用真实虚拟机验证了这套隔离。其中有一台对照机，地址和外网在同一网段、但插在内网 VLAN 上：外网机器 ping 不通它，说明挡住流量的确实是 VLAN，而不是路由。

## 检测原语

按 MVP2 第三节的原则，检测的是玩家达成了什么状态，不管他敲了什么命令。`LevelRun` 只看当前这一步的条件：满足了就推进，后面的步骤不会被提前满足。

| type | 含义 | 通路 |
| --- | --- | --- |
| `ping` | `from` 成功 ping 通 `to`，也就是交换机上看到了 `to` 回给 `from` 的 echo 应答 | 交换机 |

判定不让客户机自己去 ping。那样做的话，抓包面板上会凭空冒出玩家没敲过的流量，以后管理员也会看到判定器自己留下的痕迹。

新增原语的步骤：

1. 在 `LevelDefinition.cs` 里加一个 `LevelCheck` 子类，再加一行 `[JsonDerivedType]`。
2. 在 `LevelRun.Observe`（网络事件）里接上判定。

走控制通道的客户机状态检测，等跳板扫描真正用到时再加。

## 管理员的专用 tty

管理员是游戏逻辑驱动的假人，但他登录机器的方式是真的：客户机的 `ttyS2` 上跑着真的 getty，他用真的账号经真的 `login` 进去。于是他留下的痕迹也全是真的 —— 会话记录里有他、`ps` 里有他的 shell、他动过的文件就是被动过。玩家能察觉管理员来过，这正是 MVP2 要的对手感。

和隐藏控制通道的分工：

| | ttyS1 隐藏控制通道 | ttyS2 管理员 tty |
| --- | --- | --- |
| 给谁用 | 步骤判定 | 管理员假人 |
| 玩家能否察觉 | 不能，也碰不到 | 能，`ps` 里看得见他的会话 |
| 留痕迹 | 不留 | 留，而且是真的 |

- 哪台机器有管理员，就给它配 `Admin`（账号 + 口令），QEMU 才会多开这个串口。没有管理员的机器里连 `/dev/ttyS2` 都不存在，玩家看不出这台机器「本来可以被谁登录」。
- 账号和口令经内核参数传给客户机，客户机 init 第一次启动时建号。真的 `/proc/cmdline` 已经被伪装层盖掉，玩家读到的是伪造的那份。
- 宿主侧用 `TtySession` 驱动：登录、敲命令、读输出。它认的是 shell 自己的提示符，而不是在命令后面追加随机标记 —— 那种标记会出现在玩家的 `ps` 里，一眼就是自动化脚本。
### 查岗与白名单

关卡文件里给 `admin` 就有他：

```jsonc
"admin": {
  "machine": "jump01",          // 他查哪台机器；那台机器会因此多一个登录终端
  "user": "opsadm",
  "firstPatrolSeconds": 90,     // 进关后多久来第一次
  "intervalSeconds": 120,       // 之后每隔多久来一次
  "jitterSeconds": 25,          // 间隔的随机浮动，不让玩家掐着秒表干活
  "threshold": 75,              // 威胁评分到这个数就算暴露
  "processWeight": 25,          // 发现一个白名单外的进程扣多少分
  "allowProcesses": []          // 这台机器本来就该有的进程
}
```

上面这几个数就是 MVP2 说的难度旋钮，现在还只是关卡里的常数，将来接到难度 / 辅助依赖轴上。

他每次来做的事：登录 → `ps` → 对照白名单 → 有发现就扣分 → 退出登录。

**为什么是白名单而不是黑名单。** 黑名单要求我们预先想到玩家会用什么工具，而玩家一定会用我们没想到的东西。白名单只需要说清楚这台机器平时长什么样，这是关卡作者真的知道的事。

- 匹配的是整条命令而不是进程名，`nc -l -p 4444` 和 `nc example.com 80` 在关卡里可以是两回事。模式里可以用 `*`。
- 客户机开机自带的那批（内核线程、init、getty、管理员自己的 shell）由代码里的基准白名单兜底，关卡不用重复写。
- 内核线程一律放过：玩家伪造不了，算进来的话换个内核版本白名单就要重写。

**评分规则：**

- 同一条痕迹只算一次。管理员每次来都看得见那个还在跑的进程，按次累加的话玩家做什么都来不及，分数只取决于他动作有多慢。
- 分数到阈值就是任务失败。失败后按 MVP2 的设计应该能用快照复位重来，那套还没做，现在只能退回选关重进。
- **每一分都挂着一句说得出口的理由**：哪台机器、哪条进程、什么用户、哪个终端。玩家被扣分时要能看懂是哪条痕迹出卖了他 —— 这条护栏现在就得守住，等评分规则复杂起来再补，它就退化成玄学了。

界面上有一块管理员面板：他现在在不在、下次查岗的倒计时、威胁评分条，以及他已经发现的东西。没有发现时那一栏是空的 —— 否则玩家能靠界面反推自己有没有留痕。

还没做的：日志与文件痕迹的检查（现在只看进程）、快照复位、以及评分的精细化。

## 现有关卡

- `lab-ping` 联网实验场（教学，可玩）：由 M2 的验证壳改写而来。三端验证的自检也跑这一关，自检会在 backup 上 ping web01，然后等判定完成。
- `jump-scan` 跳板扫描（实战，草稿，需要先完成 lab-ping）：五个步骤照 MVP2 第二节列出，还都没有判定。网络分两段：外网 `outside`（VLAN 10，10.0.0.0/24）和内网 `inside`（VLAN 20，172.16.5.0/24）。
  - ws：玩家机，只在外网。
  - jump01：跳板机，两边各一块网卡。
  - files01：内网文件服务器，只在内网。

## 开发用开关

- `GAMEHACKER_TYPE=机器名:命令;机器名:命令`：截图前先在这些机器的终端里敲几条命令，用来截某个特定状态。
- `GAMEHACKER_SCREENSHOT_DELAY=秒`：截图前多等一会儿，用来等某件事发生（比如管理员来查岗）。
- `GAMEHACKER_LEVEL=<id>`：启动后跳过选关界面，直接进这一关。编辑器里可以无视锁定和草稿状态；发布版本仍然要满足解锁条件。
- 选关界面上的「无视解锁（编辑器）」勾选框只在编辑器里显示。
- 自检和截图（`GAMEHACKER_SELFTEST` / `GAMEHACKER_SCREENSHOT`）默认进 `lab-ping`，并且不写存档。

## 导出时注意

关卡 JSON 不是 Godot 资源。导出预设的「非资源文件」过滤里要加上 `levels/*.json`，否则它们不会被打进 .pck。

# 关卡系统

MVP2 的第一块：选关界面和关卡格式。跳板扫描的内容还没做，这里先把「选一关 → 进去 → 按步骤推进 → 通关存档 → 解锁下一关」的管线跑通。

## 流程

```
LevelSelect.tscn（主场景）──选关──▶ Level.tscn ──返回 / 通关──▶ LevelSelect.tscn
        ▲                                  │
        └──── GameState（autoload）────────┘
              关卡目录 · 通关进度 · 当前关卡
```

- 场景切换用 `ChangeSceneToFile`。旧场景整个释放，所以当前关卡放在常驻的 `GameState` 上传递。
- 离开关卡时由 `Level._ExitTree` 同步关掉虚拟机，和以前退出游戏走同一条路。
- 进度存在 `user://progress.json`，只记「完成了哪些关」。解锁状态按 `requires` 现算，所以改了关卡依赖，老存档也自动对得上。
- 存档损坏时不会让游戏打不开：进度按空处理，选关界面底部会提示。

## 关卡文件

放在 `src/GameHacker.Godot/levels/<id>.json`，文件名要和 id 一致。可以写 `//` 注释。

```jsonc
{
  "id": "lab-ping",              // 存档里记的就是它；只用小写字母、数字、连字符
  "title": "联网实验场",
  "track": "tutorial",           // tutorial 教学 | mission 实战
  "order": 0,                    // 同一条线里的排序
  "status": "playable",          // playable | draft（草稿关只有编辑器里能进，步骤可以没有判定）
  "requires": [],                // 先完成哪些关
  "summary": "一句话",
  "briefing": "任务简报",
  "networks": [                  // 每个网段是交换机上的一个 VLAN
    { "name": "lan", "vlan": 1, "subnet": "10.0.0.0/24" }
  ],
  "machines": [                  // 第一台是玩家的机器，它的终端总是摆在玩家面前
    { "name": "web01", "nics": [ { "network": "lan", "ip": "10.0.0.1" } ],
      "persona": "workstation", "disk": "alpine-main", "memory": 512 },
    // 别人的机器默认没有终端。要么白送（"shell": true，教学关用），
    // 要么让玩家自己从网络上进去（"access"，见下一节）
    { "name": "backup", "nics": [ { "network": "lan", "ip": "10.0.0.2" } ], "persona": "legacy-server",
      "access": { "port": 2222, "user": "svc-backup", "sudo": true } }
  ],
  "steps": [
    { "id": "link", "title": "两台机器互通", "hint": "…",
      "check": { "type": "ping", "from": "backup", "to": "web01" } }
  ]
}
```

加载时（`LevelCatalog.Parse`）会一次性校验下面这些，发现的错误攒齐了一起报：

- 字段名拼错
- 网段：VLAN 号超出 1..4094 或重复、subnet 写错或主机位不为零
- 网卡：接了不存在的网段、IP 不在所接网段里、占用网络地址或广播地址、一台机器两块网卡接同一个网段、网卡数不在 1..4
- 检测类型不存在
- 检测条件引用了不存在的机器
- id 或机器名重复
- IP 不合法
- 人设不存在
- `requires` 指向不存在的关，或者解锁条件成环
- 可玩关的某一步没有判定
- 一台机器既白送终端（`shell`）又开维护口（`access`），或者玩家自己那台机器开了维护口
- 维护口的端口和服务抢同一个、账号名不合法

单元测试 `仓库里的关卡文件都能通过校验` 会把仓库里的关卡文件全部过一遍。

## 网段与 VLAN

交换机上每个 VLAN 开一个监听口，全部是 access 口。虚拟机的网卡连到哪个口，就属于哪个 VLAN。

- **身份由连接决定。** 客户机看到的是普通网卡，不知道也改不了自己在哪个 VLAN。
- **帧只在同一 VLAN 内转发。** MAC 表按 (VLAN, MAC) 分开学，广播也只在本 VLAN 内泛洪。
- **客户机自己打了 802.1Q / QinQ 标签的帧一律丢弃。** 否则玩家手工造一个带标签的帧，就能跳进别的 VLAN。
- **多网卡。** 网卡按顺序成为客户机里的 eth0、eth1……，eth0 的地址经内核参数 `m0.ip` 传进去，eth1 起是 `m0.ip1`、`m0.ip2`。跳板机就是一块网卡在外网、一块在内网。
- **抓包。** 面板多了 VLAN 列，过滤框输入 `vlan20` 就只看这个网段。导出的 pcap 会给每帧补上 802.1Q 标签，Wireshark 里可以按 `vlan.id` 过滤。

**多层内网怎么叠。** 一层一个 VLAN，层与层之间放一台双网卡的机器（跳板机就是这个形状）：外网 → 办公网 → 核心网，就是 3 个 VLAN 加两台跳板机。层数不受限，一台机器最多 4 块网卡。测试 `多层内网_每层只和自己这层通` 覆盖了三层的情况。

现在**还没有**、等关卡真要用再加的东西：

| 缺的能力 | 什么时候需要 | 备注 |
| --- | --- | --- |
| trunk 口（一块网卡带多个 VLAN 的标签） | 想让玩家玩 VLAN 跳跃，或者一台机器要看多个网段又不想插那么多网卡 | 现在 access 口一律丢弃带标签的帧，加 trunk 时要把「哪些口允许带标签」做成配置 |
| 三层转发与访问控制（路由器 / 防火墙） | 层与层之间要能按端口放行，而不是全通或全不通 | 现在跨层只能靠双网卡的机器自己转发 |

集成测试 `跳板拓扑_两块网卡各进一个_VLAN_外网够不着内网` 用真实虚拟机验证了这套隔离。其中有一台对照机，地址和外网在同一网段、但插在内网 VLAN 上：外网机器 ping 不通它，说明挡住流量的确实是 VLAN，而不是路由。

## 玩家面前只有自己的终端

**一台机器的 shell，要么是玩家自己的，要么是他打进去的。** 界面上默认只摆第一台机器（玩家的机器）的终端；别人的机器不给终端，玩家要在上面干活就得从自己的终端连过去。

早先每台机器都摆一个终端，那只是调试时方便看。可它把关卡整个架空了：跳板机的 root shell 白送到手，「借一台跳板机穿进内网」就只剩下「在那个已经打开的窗口里敲一行 echo 1」。玩家学不到任何东西，因为最难的那一步被跳过了。

两种例外，都要在关卡文件里明写：

| 写法 | 什么时候用 |
| --- | --- |
| `"shell": true` | 教学关、特殊关。白送 shell 是为了把某个机制摊开讲，不是实战关的常态 |
| `GAMEHACKER_ALL_SHELLS=1` | 调试。把所有机器的终端都摆出来，不必改关卡文件 |

看不见的机器照样建终端节点，只是那一栏不显示 —— 串口、桥接、resize 全都照常工作，自检和截图还能往它的控制台里敲字。

### 维护口：玩家怎么进别人的机器

```jsonc
"access": { "port": 2222, "user": "svc-backup", "sudo": true }
```

客户机上真的会跑起这么一个东西：

```
nc -lk -p 2222 -e /usr/sbin/rlogind
```

`rlogind` 是个 shell 脚本，摆在机器上（玩家进去之后读得到它 —— 这机器怎么认人是可侦察的）。它读账号口令，用 `cryptpw` 比对哈希，过了就 `su` 成那个账号。所以：

- 玩家 `netstat` 扫得到这个端口，`ps` 里看得见自己的会话，管理员也看得见；
- 口令敲错了会进系统日志（`rlogind: FAILED LOGIN for …`）；
- 这个进程能被杀掉 —— 杀了自己就再也登不进来。

**口令每局现生成**，关卡文件里不留，和管理员的账号同一个规矩。玩家从当前步骤的提示里知道自己手上有什么：提示文本里可以写占位符，进关时换成这一局真的那些值。

| 占位符 | 换成 |
| --- | --- |
| `{jump01.user}` | 账号名 |
| `{jump01.password}` | 这一局的口令 |
| `{jump01.port}` | 维护口端口 |
| `{jump01.ip}` | 那台机器第一块网卡的地址 |

放在提示里而不是任务简报里：简报在选关界面就要显示，那时这一局还没开始，口令还不存在。

**那个口没有 pty。** 裸套接字上的 shell 就是这样 —— 老式维护口本来也是这样。具体后果：

- 提示符要靠 `sh -i` 自己打，而且**必须 `+m` 关掉作业控制**。不关的话 shell 起来是哑的，连上去一个字都不回（实测踩到过，三个变体里只有这一个能用）。
- `sudo` 问不了口令（没有 tty 就 `no tty present`），所以 `"sudo": true` 给的是免口令的规则。真正的提权留给以后的关卡。
- 玩家在同一个终端里干活，所以**一次只能在一个地方**：要回自己的机器上敲命令，得先 `exit`。这是真实的，也是这一关节奏的一部分。

### 机器自带的东西自动进白名单

维护口的监听进程、经它登录进来的那个会话、关卡摆的备份服务 —— 都是**这台机器本来的样子**，不是玩家带来的。加载关卡时（`LevelCatalog.WithHouseKeeping`）自动补进管理员的 `allow`，作者不用手抄：

- 抄漏了，管理员就为机器自带的东西把玩家抓了 —— 一进去就被举报，这一关谁也过不了；
- 端口一改，手抄的那份还会悄悄失效。

「掩盖」那一步和管理员用的是同一份白名单，所以补一次两边都对得上。

**玩家正登录着不算痕迹。** 那个口就是给人用的。真正会暴露他的是留下来的东西：转发没关、工具没删、端口没收、日志被删短。

## 检测原语

按 MVP2 第三节的原则，检测的是玩家达成了什么状态，不管他敲了什么命令。`LevelRun` 只看当前这一步的条件：满足了就推进，后面的步骤不会被提前满足。

| type | 判定什么 | 通路 | 字段 |
| --- | --- | --- | --- |
| `ping` | from 成功 ping 通了 to —— 交换机上看到了 to 回给 from 的 echo 应答。看应答而不是请求：请求发出去不代表通 | 交换机 | `from`、`to` |
| `traffic` | 交换机上出现过这样的包。字段都可以不写，不写就是不限；用来表达「连过那个端口没有」「对着目标发过东西没有」 | 交换机 | `from`、`to`、`network`、`protocol`、`port`、`times` |
| `route` | from 的包进得了 network，而且回得来 —— 隧道通了。只有中间那台两头插网卡的机器能把它转过去，所以这是铁证 | 交换机 | `from`、`network` |
| `scan` | 有人在 network 里挨个试地址：窗口内问候了 hosts 台以上不同的主机。写了 finds 还要求真的扫到那台机器（它应了答） | 交换机 | `network`、`hosts`、`withinSeconds`、`finds` |
| `file` | machine 上存着一份内容是这个哈希的文件 —— 东西到手了。存成什么名字、放哪个目录都行，只认内容 | 客户机 | `machine`、`sha256` |
| `process` | machine 的进程表里有这样一个进程 —— 有人在那台机器上。clean 的正面：远程登录进去了没有、后门还在不在、那个服务确实起来了没有 | 客户机 | `machine`、`user`、`command`、`times` |
| `clean` | machine 上看不出有人来过：白名单外的进程没了，转发也关回去了。白名单和管理员用的是同一份 | 客户机 | `machine` |
| `patrol` | 管理员连着查了 patrols 次岗，一次也没看出什么。让对手来验收，不需要任何额外探查 | 管理员 | `patrols` |
| `all` | 里面的条件全部满足。各条各自记账、不要求同时成立：先满足的那条会记着 | 组合 | `checks` |
| `any` | 里面的条件满足任意一条。一件事有好几种正当做法时用它 | 组合 | `checks` |

这张表是从 `CheckTypes` 那份清单生成的，代码里加了原语却不登记会有测试报红 —— 清单是写关卡的人唯一要看的目录。

**它们是零件，不是某一关的逻辑。** 每个原语只描述一件与关卡内容无关的事，关卡文件把它们挑出来拼。第二关要「探测玩家有没有发过某个包」「有没有扫到目标」「有没有把文件拿到手」，直接写进 JSON 即可，不必再写一行 C#。

一步要好几个条件时不新写原语，用 `all` / `any` 拼，可以任意嵌套：

```jsonc
{ "id": "exfil", "title": "带着东西全身而退",
  "check": { "type": "all", "checks": [
    { "type": "file",  "machine": "ws", "sha256": "…" },
    { "type": "clean", "machine": "jump01" }
  ] } }
```

`all` 里各条各自记账，**不要求同时成立**：先满足的那条会记着，不会因为后来状态变了又掉回去。已经满足的那几条也不会再去问客户机。

三条通路的分工：

- **网络行为看交换机。** 判定不让客户机自己去 ping 或者扫。那样做的话，抓包面板上会凭空冒出玩家没敲过的流量，管理员也会看到判定器自己留下的痕迹。
- **客户机内部状态问客户机。** 见下一节。
- **「有没有被发现」听管理员的。** 他本来就会按自己的节奏登录、翻看，判定只是听他的结论，一次多余的探查都不用加。

几处值得记住的判定细节：

- `route` **必须看回程**。只看去程的话，玩家在跳板机上打开了转发、内网那边却不认识回去的路，判定也会亮 —— 然后下一步扫描怎么也做不出来。
- `scan` **必须把 ARP 算上**。扫一个 /24 而里面只有一台机器时，唯一有回应的那个地址才会产生 IP 包，其余两百多次试探全是没人应答的 ARP 询问；只数 IP 包的话，最像扫描的那部分恰好全被漏掉。
- `scan` **不认发起者**。玩家的包经跳板机转发进来时，替他挨家挨户敲门的是跳板机，想认也认不准。
- `clean` **和管理员共用一份白名单**（关卡里的 `admin.allow`）。玩家的通关条件和对手的判断标准必须是同一个，否则会出现「系统说你清干净了，管理员却还是把你抓了」。
- 日志被删短了**不在 `clean` 里管**，那是管理员的记性（他从进关就一直在看）。删日志不会卡住判定，但会让他起疑 —— 这正是「掩盖」和「删除」的区别。
- `patrol` 看的是**这次什么都没看见**，不是「没有新发现」。同一处痕迹只算一次怀疑度，他第二次看见那个还在跑的进程时新发现是空的；照「没有新发现」判的话，玩家被抓住一次之后干等就能过这一步。

### 掩盖不是一个步骤

**实战关里不把「掩盖痕迹」列进任务步骤。** 它是隐形的：没做，后果是管理员找到你。

列出来会坏两件事。一是判定一旦亮绿，就等于告诉玩家「你清干净了」—— 而管理员看的东西只要比这一步多一样，玩家就会在被告知完成之后挨打，这是最难受的一种体验。二是列出来就等于把该清的东西列成了清单，玩家照着做即可，不必去想自己到底动过什么。

所以：

- **实战关**：不列步骤，只在任务简报里提一句（「听说这家的运维很较真」）。玩家知道有这么回事，但不知道清单。该清什么，靠他自己想 —— 而管理员每一条发现都说得出理由，所以挨打之后他学得会。
- **教学关**：反过来，明确列成任务目标，用 `clean` 判定，把机制摊开讲。学会了再进实战关。

`clean` 这个原语因此主要是给教学关用的。

新增原语的步骤：

1. 先想想现成的零件拼不拼得出来 —— `traffic` 加上 `all` / `any` 能表达的事比看上去多。
2. 真要加的话，在 `LevelCheck.cs` 里加一个 `LevelCheck` 子类，加一行 `[JsonDerivedType]`。
3. 实现 `CreateTracker`：跨事件的记忆放在 tracker 里，`LevelCheck` 本身是关卡文件里的一段不可变数据。
4. 要看客户机内部状态的话，在 tracker 上重写 `Wanted`。组合条件会自动把已经满足的那几条摘掉。
5. 在 `CheckTypes` 里登记一条（写清楚它判定什么、给个能直接抄的例子），再把生成的表贴进上面那张 —— 漏了会有测试报红。
6. 参数有取值范围的，在 `LevelCatalog.ValidateCheck` 里加校验 —— 写错了要在加载时就说，别等玩到那一步才发现判定永远不亮。

**判定读到的快照，没问到的那几样是 null 不是空。** 一份只回答了「有没有那个文件」的答复，它的进程表是「没问」而不是「一个进程都没有」；不分清楚的话，`clean` 会把别人的答复当成「这台机器上什么都没跑」，当场判过。新写要看客户机的原语时，记得先确认答复里真的有你要的那一样。

## 私有 API：问客户机内部状态

「文件到我机器上了没」「痕迹清干净了没」不是包，交换机永远看不见。这类事只能问客户机自己，这就是私有 API 存在的全部理由。

它走的是已有的隐藏控制通道（ttyS1，玩家看不见也碰不到），**只有三样，而且全是只读的**：

| probe | 问什么 | 客户机上实际跑的 |
| --- | --- | --- |
| `ps` | 进程表原样回来，谁算可疑由宿主按关卡白名单判断 | `ps -o pid,user,tty,args` |
| `forward` | IPv4 转发开关 | `cat /proc/sys/net/ipv4/ip_forward` |
| `file <sha>` | 这台机器上有没有内容是这个哈希的文件 | `find` + `sha256sum`，只找 `/root /home /tmp /var/tmp` |

几条刻意的设计：

- **不做「宿主发一条 shell 命令、客户机执行」的通用形式。** 那等于在客户机里开了一个玩家看不见的 root 后门，一旦判定需要什么就随手加一条，到最后谁也说不清这条通道能做什么。要加能力就加一项具名的、只读的 probe。
- **比对放在客户机里做**，串口上只回一个 0/1，不把整块内容搬过来。
- **内容一律 base64。** 进程表是多行的，命令行里什么字符都可能有，直接拼进 JSON 迟早会拼出一行解析不了的东西。
- **先取完再编码。** 写成 `ps | base64` 的话，`base64` 和 `tr` 会和 `ps` 同时在跑，于是出现在 `ps` 自己的输出里 —— 判定器看见的是它自己搅起的灰尘，「痕迹清干净了没」就永远过不去。实测踩到过。

### 什么时候去问（不是轮询）

`LevelRun.Wanted` 只说「当前这步想知道什么」，什么时候去问由外面的事件决定：

- 玩家在某台机器上**按了回车**（`TerminalBridge.PlayerSubmitted`）——他刚让这台机器做了点什么；
- 交换机上**过了包**——文件是经网络过来的，敲完回车之后它还要传一会儿；
- 管理员**查完一次岗**。

当前这步不看客户机内部状态时（`Wanted` 为 null），一次也不问。同一时刻只许有一次探查在飞，飞行期间来的触发记一笔、落地后补做一次。

这样安排不是洁癖：每次探查都要在客户机上真的跑几条命令，那几条命令会出现在玩家的 `ps` 里、会占着串口。判定器应当在玩家做了事之后才出现一瞬间，而不是每三秒在他机器上踱一次步。

顺带一提，按键只是**触发时机**，判定本身还是看状态 —— 那里拿到的是一串按键字节，连行内容都没拼出来。

### 摆在机器上的东西

关卡可以给机器摆文件和服务，都是真的：

```jsonc
{ "name": "files01",
  "nics": [ { "network": "inside", "ip": "172.16.5.20" } ],
  "gateway": "172.16.5.1",                                  // 内网机器要有网关，玩家的包才回得去
  "files": [ { "path": "/srv/backup/ledger.txt", "text": "…" } ],
  "services": [ { "port": 9000, "file": "/srv/backup/ledger.txt" } ] }
```

- 文件内容经内核 cmdline 传进去（base64），而 `/proc/cmdline` 已经被伪装盖掉，玩家读不到那份原文。
- 服务是客户机上真的 `nc -lk -p 端口 -e cat 文件`：一个没有认证、连上就给的老式备份口。它在 `ps` 里看得见、能被杀掉，玩家也能自己拿来用。
- **跳板机和玩家自己的机器不给网关** —— 把两边接起来正是玩家要做的事。

## 管理员的专用 tty

管理员是游戏逻辑驱动的假人，但他登录机器的方式是真的：客户机的 `ttyS2` 上跑着真的 getty，他用真的账号经真的 `login` 进去。于是他留下的痕迹也全是真的 —— 会话记录里有他、`ps` 里有他的 shell、他动过的文件就是被动过。玩家能察觉管理员来过，这正是 MVP2 要的对手感。

和隐藏控制通道的分工：

| | ttyS1 隐藏控制通道 | ttyS2 管理员 tty |
| --- | --- | --- |
| 给谁用 | 步骤判定 | 管理员假人 |
| 玩家能否察觉 | 不能，也碰不到 | 能，`ps` 里看得见他的会话 |
| 留痕迹 | 不留 | 留，而且是真的 |

- 哪台机器有管理员，就给它配 `Admin`（账号 + 口令），QEMU 才会多开这个串口。没有管理员的机器里连 `/dev/ttyS2` 都不存在，玩家看不出这台机器「本来可以被谁登录」。
- 账号和口令经内核参数传给客户机，客户机 init 第一次启动时建号。真的 `/proc/cmdline` 已经被伪装层盖掉，玩家读到的是伪造的那份。
- 宿主侧用 `TtySession` 驱动：登录、敲命令、读输出。它认的是 shell 自己的提示符，而不是在命令后面追加随机标记 —— 那种标记会出现在玩家的 `ps` 里，一眼就是自动化脚本。
### 他怎么查岗

他是个人，不是巡检脚本：

- **每次只随手看几样。** 例行动作各有概率，每次登录抽几件做，顺序也是乱的。玩家没法靠「他每次都查这几样」来规划。
- **两条命令之间会停一下**，所以玩家有机会在终端里察觉他正在看。
- **看到小事只是起疑。** 怀疑度攒到 `sweepAt`，下次来就把机器从头翻一遍（`sweep`），而且每处发现都乘 `sweepMultiplier`——那一遍基本什么都藏不住。
- **一次什么都没查出来，疑心会退一点**（`calmPerPatrol`）。没有这条的话怀疑度只增不减，玩家迟早必然暴露，隐蔽就不是一门手艺，只是拖时间。
- 怀疑度到 `exposedAt` 就是查实，任务失败。

**正因为平时那几眼不致命，高手模式才成立**：`visibility` 设成 `hidden`，界面上不再显示他的任何动向，玩家只能自己从机器上看出他来过（比如 `ps` 里他的会话）。

### 他查什么

| check | 在客户机上敲什么 | 看出什么 |
| --- | --- | --- |
| `processes` | `ps` | 白名单外的进程 |
| `sessions` | `ps` | 除了他自己和常态终端，还有谁登录着 |
| `log` | `wc -l` + `tail` 系统日志 | 刺眼的记录，以及**日志被删短了** |
| `services` | `ps` | 该一直跑着的服务不见了（玩家嫌它碍事杀掉了） |
| `ports` | `netstat -ltnu` | 白名单外的监听端口。进程名起得再无害，端口也藏不住 |
| `files` | `find /tmp /var/tmp /dev/shm -type f` | 临时目录里来路不明的文件，玩家的工具多半扔在这 |
| `forwarding` | `cat /proc/sys/net/ipv4/ip_forward` | 这台机器在替别人转发包，可它不是路由器 |
| `script` | `sh ~/bin/<脚本>` | 他自己的运维脚本打印出来的东西（见下文「三档管理员」） |

他自己那个终端上的进程（他的 shell、他正在跑的脚本）不算可疑。

日志那项是有记性的：他记得上次看到多少行，凭空短了一截当然会问为什么。这正是「掩盖」和「删除」的区别——玩家得让日志看起来自然，而不是让它消失。

终端在 busybox 的 `ps` 里是设备号（`4,64`），代码里会翻成 `ttyS0` 这样的名字，所以白名单写名字就行。

> **坑：busybox 的 `ps` 把 USER 列截到 8 个字符。** `svc-backup` 在输出里是 `svc-back`。按用户名判定的地方（`process` 原语）要容忍这一截，否则关卡里凡是写了长名字的账号，那一步**永远不亮**，而 `ps` 的输出看上去完全正常 —— 实测踩到过，`ProcessLine.IsUser` 就是为这件事存在的。

### 三档管理员

同一台机器换个人来查，区别在手法和脾气上。关卡管「这台机器长什么样」（白名单、多久来一次），档位管「这个人怎么查」。

| 档位 | 怎么查 | 起疑之后 |
| --- | --- | --- |
| `junior` 实习运维 | 只跑家目录 `~/bin` 里的巡检脚本（默认 `daily-check.sh` 查服务和会话，偶尔跑 `full-check.sh` 再加进程和日志），脚本没打印的他就看不见 | 阈值 ×1.5，疑心消得快（×2）；彻底检查也只是跑 `full-check.sh` |
| `regular` 运维 | 照关卡写的 `routine` 来 | 照关卡写的来 |
| `senior` 资深运维 | 进程、端口、服务、会话、日志、临时文件，一次看 3~6 样，手快（停顿 ×0.6） | 阈值 ×0.25，一处异常就够；60% 当场接着全查而不是等下次；彻底检查倍数 +1；可能改口令 |

叫「实习运维 / 运维 / 资深运维」而不叫新手老手，是为了不和玩家的游玩模式混在一起。

**谁来跟着游玩模式和关卡走，没有单独的难度。** 游玩模式（新手 / 高级 / 专家，MVP2 第二节那根「辅助依赖轴」）在选关界面上全局选一次、跟着存档走。新手模式给初学者，专家模式贴近实际渗透，对手有多强是模式的一部分。关卡没写的话按默认概率：

| 游玩模式 | 实习运维 | 运维 | 资深运维 |
| --- | --- | --- | --- |
| 新手 | 80% | 20% | 0% |
| 高级 | 30% | 50% | 20% |
| 专家 | 5% | 35% | 60% |

关卡可以用 `skillOdds` 按模式改概率（每个模式的概率加起来要是 1，没写的模式用默认），或者写 `"skill": "senior"` 强制那一档、不管什么模式。开发时可以用 `GAMEHACKER_ADMIN_SKILL` 盖过一切。现在模式只影响管理员；提示、步骤、额外工具按模式派生是之后的事。

**档位对怀疑度用倍率，不直接给值。** 阶段（`stages`）会整套换掉怀疑度规则，档位要是也直接给值，两边就只能有一个说了算；用倍率的话，「到了掩盖那一步他更敏感」和「资深运维本来就敏感」能叠在一起。暴露阈值 `exposedAt` 和来的频率不受档位影响，那是关卡的输赢线和节奏。

**实习运维的脚本是真的。** 开局他会登录一次，把脚本写进 `/home/opsadm/bin`（登录记录里因此有一次很早的登录；写脚本的那串命令会从他的命令历史里清掉）。脚本每段前面打一行 `== services ==`，他按段去看。于是：

- 玩家翻到这些脚本，就知道他每天看什么——这是侦察。
- 把脚本改成少打印一段，他看不出来——这是真实的攻击手法，留给玩家。
- 但脚本没了、被清空、跑不起来，他每天跑的东西突然不灵了，这个他看得出来。

**改口令。** 资深运维每次查岗有 3% 的可能顺手改口令，看出东西后升到 35%，改的是 `passwordTargets` 里的账号（通常就是玩家拿到的那个），玩家之后就登不进来了。他用的是 `sudo passwd ops`：客户机的 busybox 没有 setuid，改别人的口令要靠 sudo（他在 sudoers 里，要口令）。新口令是在 `passwd` 的提示后面敲的，不在命令行上，所以不进命令历史。玩家能察觉的痕迹：他的命令历史里有 `sudo passwd ops`，sudo 在系统日志里记了一笔，`/etc/shadow` 被改过。

**关卡里写的检查项，每一档都要查得到。** 实习和资深运维自带一套手法，会<b>整个盖掉</b>关卡的 `routine`。关卡写了某项检查、某一档却没有对应的一条，那条痕迹对这一档就等于不存在 —— 关卡作者不会知道，玩家碰上那一档就白清了。加检查项时三档都要顾到（实习那档在他的运维脚本里加），有测试盯着。

### 关卡文件里怎么写

```jsonc
"admin": {
  "machine": "jump01",
  "user": "opsadm",
  "visibility": "shown",              // hidden = 高手模式
  "schedule": { "firstPatrolSeconds": 90, "intervalSeconds": 120, "jitterSeconds": 25,
                "minActions": 1, "maxActions": 3, "pauseMin": 1.5, "pauseMax": 5 },
  "suspicion": { "sweepAt": 40, "exposedAt": 100, "calmPerPatrol": 5, "sweepMultiplier": 2 },
  "allow": {
    "processes": ["syslogd*"],
    "sessions": ["ttyS2", "ttyS0"],   // 他自己的终端；物理控制台是这台机器的常态
    "services": ["syslogd"],
    "logRedFlags": ["nc ", "tcpdump", "/tmp/"],
    "ports": ["tcp/22"],              // 本来就该监听的端口；只写 "22" 表示 tcp/udp 都算
    "files": ["/tmp/.X*"]             // 临时目录里本来就有的文件，fileDirs 可改查哪些目录
  },
  "routine": [
    { "id": "sessions", "check": "sessions", "chance": 0.6, "weight": 20 },
    { "id": "log",      "check": "log",      "chance": 0.5, "weight": 25 }
  ],
  "sweep": ["sessions", "log"],       // 留空就是全做一遍
  "skill": "senior",                  // 可选：强制档位
  "passwordTargets": ["ops"],         // 可选：资深运维起疑时会改掉这些账号的口令
  "skillOdds": {                      // 可选：按游玩模式改三档出现的概率
    "novice": { "junior": 1 }
  },
  "scripts": [                        // 可选：他家目录里的脚本，不写就是默认那两个
    { "name": "daily-check.sh", "checks": ["services", "sessions"] },
    { "name": "full-check.sh",  "checks": ["services", "sessions", "processes", "log"] }
  ],
  "tiers": {                          // 可选：在某一档的内置做派上只改几处
    "senior": { "sweepOnTheSpotChance": 1, "passwordChanceOnFinding": 0.6 },
    "junior": { "routine": [ { "id": "daily", "check": "script", "script": "daily-check.sh", "chance": 1 } ] }
  },
  "stages": {                         // 键是步骤 id：玩家推进到那一步，他就变成这样
    "cover": { "schedule": { "intervalSeconds": 60, ... },
               "suspicion": { "sweepAt": 25, ... } }
  }
}
```

**阶段（`stages`）是按关卡步骤挂的。** 玩家推进到某一步，管理员的作息、脾气、要查的东西、甚至显不显示都可以整套换掉——比如玩家开始扫内网之后他来得更勤，到了掩盖那一步一点小事就翻脸。换阶段不会清空已经攒下的怀疑度：他不会忘掉之前看见的事。

关卡加载时会校验这些：概率要在 0..1、浮动要小于间隔、`sweepAt` 不能大于 `exposedAt`（否则他永远不会认真查）、`sweep` 和 `stages` 里的 id 要对得上。任何模式下可能抽到的每一档都要说得通：可能抽到运维就得有 `routine`（强制成资深运维、或者各模式都抽不到运维的关卡可以不写）、跑脚本的动作要指向 `scripts` 里有的脚本、不能改 root 或管理员自己的口令。

`tiers` 里能写的字段：`routine`、`sweep`、`sweepAtScale`、`calmScale`、`sweepMultiplierBonus`、`sweepOnTheSpotChance`、`passwordChance`、`passwordChanceOnFinding`、`minActions`、`maxActions`、`pauseScale`。没写的沿用内置预设（`AdminProfile.Preset`）。阶段里写了 `routine` 的话，会盖过所有档位的那套——写阶段 routine 时要想清楚实习运维也会照着它查。

**白名单而不是黑名单。** 黑名单要求我们预先想到玩家会用什么工具，而玩家一定会用我们没想到的东西；白名单只需要说清楚这台机器平时长什么样，这是关卡作者真的知道的事。客户机开机自带的那批（内核线程、init、getty、管理员自己的 shell）由代码里的基准白名单兜底，关卡不用重复写。

**同一处痕迹只算一次。** 那个还在跑的进程他每次都看得见，按次累加的话，分数只取决于玩家动作有多慢。

**每一分都挂着一句说得出口的理由**：哪台机器、什么东西、什么用户、哪个终端。玩家被抓时要能看懂是哪条痕迹出卖了他——这条护栏现在就得守住，等规则复杂起来再补，它就退化成玄学了。

界面上的管理员面板显示他在不在、下次来的倒计时、怀疑度，以及他已经看出来的东西；没有发现时那一栏是空的，否则玩家能靠界面反推自己有没有留痕。

### 客户机这边

为了让这些检查有真东西可查，客户机开机会起 `syslogd`（真的系统日志，玩家能看能改能删），并建好登录记录文件。管理员的账号在 syslogd 之前建好，免得「口令已修改」那句话落进日志里，等于告诉玩家这机器上有个什么账号。

客户机镜像里装了 sudo（`01-build-guest-initramfs.sh` 的 `EXTRA_PACKAGES`，只拷包本身，依赖要是镜像里本来就有的）。非 root 打包给不了属主和 setuid 位，开机时 `m0_setup_sudo` 补上。管理员账号建好时给他写一条 `/etc/sudoers.d` 规则：全权、要口令。反过来，玩家要是弄到了他的口令，`sudo -l` 一看就是条提权的路。

这套 busybox 的 `nc` 不能监听，玩家在目标机上能开端口的现成工具只有 `ntpd -l`（udp/123）；从别处带进来的工具另说。

还没做的：快照复位、更细的评分规则、资深运维校验脚本有没有被改过（现在谁都看不出脚本被改了，只看得出没了）。

## 现有关卡

- `lab-ping` 联网实验场（教学，可玩）：由 M2 的验证壳改写而来。三端验证的自检也跑这一关，自检会在 backup 上 ping web01，然后等判定完成。
- `jump-scan` 跳板扫描（实战，可玩，需要先完成 lab-ping）：MVP2 第二节那条五步链条。网络分两段：外网 `outside`（VLAN 10，10.0.0.0/24）和内网 `inside`（VLAN 20，172.16.5.0/24）。
  - ws：玩家机，只在外网，没有通往内网的路由。**界面上只有它一个终端。**
  - jump01：跳板机，两边各一块网卡，默认不转发，2222 口上是个老式维护口（账号 `svc-backup`，口令每局现生成）。管理员查的就是它。
  - files01：内网深处那台老机器，只在内网，网关指向跳板机，9000 口上开着没有认证的备份服务。
  - 五步：**进跳板机**（从自己的终端连维护口，用手上的账号登录）→ **建隧道**（在那台机器上 sudo 打开转发，回到自己机器上加一条路由）→ **扫描**（挨个试内网地址）→ **拿取**（连备份口把文件存到自己机器上）→ **隐蔽**（等管理员来查一遍，什么都没发现）。
  - 资深运维起疑时会 `sudo passwd svc-backup` 改掉玩家手上那个账号的口令 —— 那条路当场断掉，再也登不进来。只有资深档会这么干。
  - **「把动过的东西恢复原样」不是步骤**（见上文「掩盖不是一个步骤」）。玩家要穿进内网就得把跳板机变成路由器，走的时候不关回去，管理员那项 `forwarding` 检查就会看见 —— 任务里一个字都不会提醒他，简报里只说这家的运维很较真。
  - 集成测试 `整关能真的一步步走完_没清的痕迹由管理员找出来` 会用三台真虚拟机把这一关从头打到尾，读的就是仓库里这份关卡文件 —— 目标文件的哈希写错了、备份服务的端口写错了，它都会红。

## 开发用开关

- `GAMEHACKER_ALL_SHELLS=1`：把所有机器的终端都摆出来。正常情况下玩家只看得见自己那一台。
- `GAMEHACKER_TYPE=机器名:命令;机器名:命令`：截图前先在这些机器的终端里敲几条命令，用来截某个特定状态。
- `GAMEHACKER_SCREENSHOT_DELAY=秒`：截图前多等一会儿，用来等某件事发生（比如管理员来查岗）。
- `GAMEHACKER_ADMIN_SKILL=junior|regular|senior`：指定来查岗的管理员是哪一档，盖过游玩模式和关卡的 `skill`，用来挨个看三档的表现。
- `GAMEHACKER_LEVEL=<id>`：启动后跳过选关界面，直接进这一关。编辑器里可以无视锁定和草稿状态；发布版本仍然要满足解锁条件。
- 选关界面上的「无视解锁（编辑器）」勾选框只在编辑器里显示。
- 自检和截图（`GAMEHACKER_SELFTEST` / `GAMEHACKER_SCREENSHOT`）默认进 `lab-ping`，并且不写存档。

## 导出时注意

关卡 JSON 不是 Godot 资源。导出预设的「非资源文件」过滤里要加上 `levels/*.json`，否则它们不会被打进 .pck。
